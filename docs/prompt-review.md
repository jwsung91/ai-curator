# 프롬프트 편집 기준 검토

## 이번 변경

- 역할을 로봇 통합 엔지니어에서 로보틱스·AI 기술 편집자로 조정했다. AI 소식을 로봇 활용과 억지로 연결하지 않고 원문을 읽을 이유를 전달한다.
- 데일리 관찰과 위클리 흐름은 0~3개로 제한하고 빈 결과를 허용한다. 수집량에 따라 관찰 수를 늘리지 않는다.
- 섹션별 항목은 0~5개로 제한한다. 호환성·지원 종료·중요 수정, 개발·운영 영향, 유용한 읽을거리, 산업 동향 순으로 선별한다. 보도량은 보조 기준이다.
- 각 입력의 ID, 제목, 출처, URL, 원문 발행일, 수집일, 분류 힌트와 근거를 JSON으로 전달한다. 날짜 미상은 수집일로 대체하지 않는다.
- 재보도와 실제 후속 변경을 구분하고 기업 주장·커뮤니티 실험을 독립 검증처럼 표현하지 않도록 했다.
- 위클리 프롬프트에서 AI가 생성한 일간 관찰과 수집량 통계 힌트를 제거했다. 일간 추론의 반복이나 기사량 자체가 추세의 근거가 되는 것을 막기 위한 조치다. 리포트 하단 수집 통계는 유지한다.
- 기술명과 구체적 변경을 서브타이틀에 포함하고, 근거 없는 가속·진화 등의 표현과 기술명 임의 번역을 피하도록 했다.
- 편집 기준을 `scripts/prompt_policy.py`로 공유해 데일리·위클리 간 기준 차이를 줄였다.

## 검토 시나리오와 기대 결과

| 입력 상황 | 기대 결과 |
|---|---|
| 서로 무관한 기사 15개 | 항목 수에 관계없이 관찰 생략 가능 |
| 제목만 있고 요약 없음 | 제목에 명시된 사실만 전달하고 제목 기반 표시 |
| 기업의 성능 주장 또는 개인 실험 | 주장·실험 주체를 명시하고 독립 검증처럼 표현하지 않음 |
| 과거 발표를 오늘 수집 | 오늘 출시라고 표현하지 않음 |
| 같은 발표를 이틀간 재보도 | 하나의 사건으로 묶고 별개 추세 근거로 계산하지 않음 |
| 하루에만 나온 지원 종료 공지 | 위클리 하이라이트에 포함 가능 |
| 일간 관찰에 근거 없는 추론 포함 | 해당 관찰은 위클리 모델 입력으로 전달하지 않음 |
| 비어 있는 관찰·섹션 | 검증 통과 |
| 인용 없는 항목, 잘못된 인용 번호, 항목 수 초과 | 저장 전에 검증 실패 |
| 피드 제목에 개행·JSON 모양 지시문 포함 | 입력 문자열로 이스케이프해 필드 경계를 보존 |

## 검증 범위와 한계

오프라인 테스트는 날짜·출처·번호 보존, 입력 문자열 경계, 빈 결과 허용, 항목 형식·개수·인용 유무와 범위를 확인한다. 기존 저장 데이터로 데일리·위클리 프롬프트도 구성해 확인한다.

실제 Gemini 호출을 통한 변경 전후 생성 품질 비교는 수행하지 않았다. 인용된 자료가 주장을 뒷받침하는지, 서로 다른 기사들이 독립적인 사건인지, 중요도 순서가 적절한지는 형식 검증만으로 보장되지 않는다. JSON 인코딩 또한 프롬프트 주입을 완전히 방지하지는 않는다.

새 검증에서 인용 누락이나 형식 오류가 나오면 파이프라인은 실패하며 리포트를 저장하지 않는다. 자동 수정 재요청은 이번 변경에 포함하지 않았다. 기존 발행 리포트는 다시 생성하지 않는다.
