# 프롬프트 반복평가: 같은 입력으로 전후 각 3회

**판정: 데일리의 과도한 해석과 장황함을 줄이는 효과는 이 표본에서 반복 확인되었다. 하지만 사실 정확성과 읽을거리 보존은 불안정하며, 현재 개선안을 그대로 머지하기보다는 오류를 보완한 뒤 다시 평가할 것을 권장한다.**

## 실행 조건

- 각 사례·버전의 프롬프트 SHA-256과 입력 파일 바이트가 3회 모두 동일함을 확인했다.
- 후보 커밋은 1회차 `5329f27`, 2·3회차 `da05669`다. 그 사이 변경은 평가 문서뿐이며 프롬프트와 실행 스크립트는 같다.
- 각 회차는 별도 API 요청이다. 동일한 원본 결과를 재채점하거나 복제한 것이 아니다.
- 자동 지표는 [metrics.json](metrics.json), 생성 설정과 토큰은 각 실행의 `manifest.json`에 있다.
- 기존 프롬프트도 모든 회차에 다시 생성했다. 프롬프트 문구와 입력 표현 방식 전체의 효과를 비교하며 특정 한 문구의 인과 효과는 분리하지 않는다.

### 유지할 개선

- **데일리의 억지 연결 감소:** 개선 데일리 6건 모두 관찰을 생략했다. 기존 데일리에는 로컬 추론 업데이트와 로봇 데모·산업 소식을 묶어 통합 효과·확산·가속을 주장하는 문장이 반복 등장했다. 이 표본에서는 무리한 해석을 생략하는 편이 더 충실했다. 관찰을 적게 쓰는 것 자체가 항상 우수하다는 뜻은 아니다.
- **구체적인 제목:** 개선 데일리 6건 모두 rclrs 또는 ros2_unbag·Ollama 등 구체적인 기술과 변경을 드러냈다. 기존 제목은 '로봇 지능화 흐름', '런타임 고도화', '지속적 진화'처럼 넓은 표현이 많았다.
- **분량 안정화:** 23개 입력의 기존 데일리는 본문이 14~20개로 흔들렸지만 개선안은 11~12개였다. 관련 항목의 가치를 희생하지 않는 범위에서 상한을 두는 방향은 유효하다.
- **행사·RC 제외:** 09-24 개선안은 3회 모두 라이브 스트림, 밋업 후속 안내, 기조연설과 일반 Ollama RC 업데이트를 제외했다. 기존안은 이들을 3회 모두 포함했다. 기존안도 RC라는 표시는 유지했으므로 판별 정확도와 선별 정책의 효과를 혼동하지 않는다.

### 날짜 오류는 재현 빈도가 낮아도 해결된 것이 아니다

1회차 개선 위클리는 SDK v1.7.0, v1.8.0을 수집일인 09-21, 09-23과 연결했다. 입력 요약에 적힌 날짜는 09-18, 09-22다. 2·3회차는 해당 일자를 적지 않았다. 따라서 2회는 '정확한 날짜를 해석했다'가 아니라 **일자 단정을 피해서 이 오류가 나타나지 않았다**고 평가했다.

근거: [1회차 위클리 출력](../2026-09-26/weekly-2026-W39/after.json), 같은 폴더의 `input.json` 11·41번 항목.

### 발표 주체와 분류가 고정되지 않는다

1회차 09-24 개선안은 Google이 모델과 전용 플레이그라운드를 함께 발표했다고 썼다. 입력 11번의 도구는 Simon Willison 출처다. 2회차는 주체를 생략했고 3회차는 플레이그라운드 언급을 생략했다. 오류가 없어진 대신 주체 보존 능력이 입증된 것은 아니다.

또한 PickNik-Qualcomm 협력은 개선 데일리에서 트렌드→로보틱스→트렌드, 개선 위클리에서 로보틱스→트렌드→트렌드로 이동했다. 기업 협력을 트렌드로 배치하라는 규칙도 안정적으로 지켜지지 않았다.

### 보수적 요약과 정보 손실의 균형이 필요하다

위클리 입력 47번에는 Isaac ROS의 신규 에이전트 워크플로와 플랫폼 지원이 명시되어 있다. 개선안은 1·3회차에 이를 제외하고 단순 릴리스 사실만 전달했다. 3회차에는 별도의 cuMotion 튜토리얼이 포함되었으므로 로보틱스 기능 정보 전체가 사라졌다는 뜻은 아니다. **같은 릴리스의 입력에 있던 구체적인 기능 설명이 유지되지 않는다**는 문제다.

09-25의 모션 아키텍처 가이드는 3회 모두 빠졌다. 유용한 해설·튜토리얼을 다루겠다는 정책에 비추어, 단순 릴리스와 제품 발표만 우선하는 경향을 다시 조정할 필요가 있다.

새로 확인한 사례로는 3회차 09-24 개선안이 요약 없는 'Claude 효소 시스템 발견'을 AI 섹션에 넣었다. '(제목 기반)' 표기는 했지만, 연구 항목의 코드·재현 가능성·개발 관련성이 입력에 명확해야 한다는 선별 조건은 충족하지 못했다.

## 자동 검증과 사용량

- 18건 모두 JSON 파싱, 불릿별 인용 존재, 인용 번호 범위 검사를 통과했다.
- 개선안 9건 모두 현재 신규 형식 검증을 통과했다. 위의 날짜·주체 오류와 누락도 통과했으므로 **형식 통과율은 내용 정확도가 아니다**.
- 기존안은 신규 상한 규칙 기준으로 5/9건 통과했다. 기존 프롬프트에는 다른 분량 기준이 있으므로 4건을 기존 지시 위반이나 사실 오류로 계산하지 않는다.
- 입력 토큰 합계: 기존 39,255 → 개선 72,504, **+84.7%**.
- 추론·출력 포함 총 토큰 합계: 기존 57,482 → 개선 89,857, **+56.3%**.
- 통화 금액을 산출한 비용 비교는 아니다. 출력 안정화가 현재 입력량 증가를 상쇄하지는 못했다.

## 권장 조치

1. **날짜를 자유 서술에서 분리:** 사건 날짜는 출처의 근거 문구와 함께 구조화해 추출하고, 근거가 없으면 출력하지 않는다. 수집일을 사건 날짜로 사용했는지 별도로 검증한다.
2. **항목 통합 전에 주체·사건을 구분:** 같은 모델을 다루더라도 제조사 발표와 제3자의 도구 공개를 별개 사실로 유지한다.
3. **선별 결과에 이유를 남김:** 해설·튜토리얼이 제외되는 이유와, 같은 사건의 구체적인 기능 설명이 포함되었는지 검토할 수 있게 한다. 최종 독자용 출력에는 내부 선별 이유를 노출할 필요가 없다.
4. **정책과 검증기 정합성 보완:** 명확한 분류 규칙, 해석 표기와 근거 기준을 검증 가능한 구조에 연결한다. 현재처럼 긴 지시문만 늘리는 방식은 피한다.
5. **프롬프트·입력의 중복 축소:** 반복되는 날짜·출처 표현과 긴 공통 문구를 줄이고, 짧은 근거 필드로 재구성한 뒤 토큰과 품질을 함께 비교한다.
6. 위 조치를 별도 후보 버전으로 만든 뒤 동일 회귀 사례와 **새로운 날짜·주제의 사례**를 함께 평가한다.

동일한 3개 입력에 대한 반복이므로 새로운 주제·데이터 분포로 일반화할 수는 없다. 이번에는 반복성을 확인하기 위해 프롬프트를 동결했으며, 위 권고의 수정·재생성은 수행하지 않았다.
