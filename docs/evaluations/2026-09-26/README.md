각 폴더의 `input.json`, `before/after.prompt.txt`, `before/after.response.txt`, `before/after.json`에 입력과 원본 응답을 보존했다. [manifest.json](manifest.json)에 모델, 설정, 프롬프트 해시, 소요 시간, 사용 토큰을 기록했다.

## 개선이 확인된 부분

### 1. 억지 로봇 통합 해석 감소

09-25 기존 관찰은 안전 데모와 모션 설계 등을 묶어 '현장 신뢰성을 보장하기 위한 필수 접근법'이라고 설명하고, Ollama와 ROS 패키지 배포를 '통합 완성도를 높이는 기반'으로 연결했다. 입력은 각각의 업데이트를 설명할 뿐 보장이나 통합 효과를 입증하지 않는다.

개선안은 관찰을 빈 문자열로 반환하고 확인 가능한 개별 소식만 남겼다. 09-24에도 기존의 엣지 로봇 배포 가능성 등에 대한 넓은 추론 3개가 제거되었다.

근거: [09-25 기존](daily-2026-09-25/before.json), [09-25 개선](daily-2026-09-25/after.json).

### 2. 제목의 구체성 향상

09-25의 '로보틱스 안전·배포 인프라 정비와 온디바이스 AI 도구의 가속화'가 'Ollama v0.34.4 릴리스 및 ROS 2 빌드팜의 ros2_unbag 배포'로 바뀌었다. 09-24도 추상적인 '미들웨어 확장·런타임 진화' 대신 rclrs와 LiteLLM의 구체적인 변경을 드러냈다.

### 3. 데일리 선별의 잡음 감소

09-24 개선안은 ROSCon 라이브 스트림, 밋업 후속 안내, RoboBusiness 기조연설을 제외하고 LiteLLM 서명 검증을 AI 섹션 첫 항목으로 올렸다. 일반 업데이트에서 Ollama RC도 제외했다. 기존안도 RC 상태 자체는 정확히 표시했으므로, 여기서 개선된 것은 안정판 판별 정확도보다 **선별 정책 준수**다.

## 남은 문제와 회귀

### 1. 위클리가 수집일을 릴리스 날짜로 바꿈 — 우선 수정

개선안은 Anthropic SDK v1.7.0 변경을 '2026-09-21', v1.8.0 변경을 '2026-09-23'로 서술했다. 그러나 입력 요약에는 각각 `1.7.0 (2026-09-18)`, `1.8.0 (2026-09-22)`가 명시되어 있다. 09-21과 09-23은 수집일이다.

Ollama 흐름에서도 발행일이 없는 입력에 수집일을 붙여 날짜별 배포 사실처럼 설명했다. 프롬프트의 날짜 구분 규칙만으로 이 오류를 막지 못했다.

근거: [개선 위클리](weekly-2026-W39/after.json)의 `weekly_themes`, [주간 입력](weekly-2026-W39/input.json)의 11·41·42·76번 항목.

권장: 흐름에서는 일자 서술을 기본적으로 생략한다. 필요한 사건 날짜는 근거 문구와 함께 별도 구조화 필드로 추출하고, `collected_date`에서 가져온 날짜를 사건 날짜로 사용할 수 없게 검증한다.

### 2. 서로 다른 발표 주체를 하나로 합침

09-24 개선안은 'Google이 ... 신규 텍스트 투 스피치 모델과 전용 플레이그라운드를 공개함'이라고 썼다. 10번은 Google DeepMind 모델 소개지만 11번 플레이그라운드의 출처·URL은 Simon Willison이다. 모델과 도구를 묶으면서 발표 주체를 Google로 통합했다.

권장: 관련 항목을 묶더라도 각 기능·도구의 주체와 인용을 별도로 보존한다. 주체가 불명확하면 생략하고 추정하지 않는다.

### 3. 보수적인 요약이 유용한 정보까지 잃음

개선 위클리의 Isaac ROS 항목은 '버전 태그가 등록되며 릴리스 풀 리퀘스트가 병합됨'에 머물렀다. 동일 입력의 47번에는 신규 에이전트 워크플로우와 플랫폼 지원 설명이 있다. 기존안은 이를 함께 인용했지만 개선안은 간단한 GitHub 릴리스 문구만 사용했다.

09-25에서는 모션 아키텍처 가이드가 제외되었다. 이는 오류라기보다 튜토리얼·해설을 읽을거리로 확대하려는 정책과 실제 선별 결과가 어긋날 수 있다는 사례다.

권장: 버전 등록·PR 병합만 있는 출처는 같은 사건의 근거 있는 기술 설명과 결합하되, 기업이 주장한 효과는 주체를 명시한다.

### 4. 분류와 표현 형식의 일관성 부족

PickNik-Qualcomm 협력은 개선 데일리에서는 트렌드, 개선 위클리에서는 로보틱스에 배치되었다. 위클리 흐름은 지정된 '해석:' 형식 대신 굵은 제목 형태로 출력했다. 형식 검증 통과가 모든 편집 정책의 준수를 뜻하지 않는다.

1. 수집일의 사건 날짜 전환 차단.
2. 관련 뉴스 통합 시 주체·근거를 항목별로 유지.
3. 릴리스 태그 나열 대신 근거 있는 기능 설명을 보존하도록 선별 규칙 보완.
4. 긴 공통 지시와 반복 입력 필드를 줄여 토큰 비용 완화.

데일리의 관찰 생략·구체적인 제목이라는 방향은 유지할 가치가 있다. 다만 이번 결과만으로 전체 품질이 안정적으로 향상되었다고 결론 내리거나 오류가 해결되었다고 간주해서는 안 된다.
