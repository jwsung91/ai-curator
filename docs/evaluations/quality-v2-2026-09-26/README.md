# 품질 우선 파이프라인 평가

## 결론

원문 발췌와 선별·작성·검토의 분리는 설명의 깊이, 출처 주체 구분, 기능 정보 보존을 개선했다. 그러나 자동 검증 통과를 사실 정확성의 보장으로 볼 수는 없다. 최종 버전은 4개 사례 모두 통과했지만, 위클리의 과도한 분량·선정 누락·문맥을 기능으로 오해하는 문제가 남아 있다. 운영 머지 전 이 부분을 추가 개선하는 것이 좋다.

## 조건과 실행 이력

- 비교 기준: `055b7cf`의 단일 호출 프롬프트와 공유 정책을 함께 고정했다. 최초 프롬프트가 아니라 앞선 1차 개선 버전과의 비교다.
- 데일리 2026-09-25(9건), 09-24(23건), 위클리 2026-W39(80건)는 저장 입력을 고정했다.
- 새로운 데일리 2026-09-10(15건)는 실행 당시 공개 원문을 수집해 저장했다. 과거 시점 재현이 아니라 원문 보강 효과를 보는 사례다. 이 사례의 before는 기존 피드 입력 방식, after는 추가 원문을 활용하므로 프롬프트만의 효과로 해석하지 않는다.
- `gemini-flash-latest`, temperature 0.2. 응답 모델 버전은 각 trace에 저장한다.
- 4회 실행 × 4개 사례 × 전후 2개 방식 = 32개 생성 시도. baseline 16개 생성, candidate 14개 검증 완료·2개 실패. **서로 다른 수정 버전을 합친 수치이므로 최종 버전의 반복 성공률이 아니다.**
- `before`의 manifest pass는 JSON 파싱 성공이며, candidate의 근거·선정 보존 검증 통과와 동등하지 않다.

최종 버전은 현재 1회 평가다. 이 버전의 반복 안정성이 충분히 입증됐다고 주장하지 않는다. 각 디렉터리에 입력, 이전 프롬프트, 전후 결과, 단계별 원본 응답과 검증 오류를 보존했다. 실패 실행도 삭제하지 않았다.

## 개선 확인

- **모델과 제3자 도구 구분**: 09-24의 Google 모델 발표와 Simon Willison 도구가 before에서는 4회 모두 별개 항목으로 유지되지 않았다. 후보에서는 run-1 병합, run-2~4 분리였다. 최종 결과는 모델과 도구의 주체도 각각 표시했다.
- **일반 프리릴리스 제외**: 초기 후보의 Ollama RC 선정 회귀를 발견했다. URL에서 릴리스 상태를 복원하고 예외 사유를 요구한 뒤 09-24의 run-2~4에서는 일반 RC를 제외했다.
- **Isaac ROS 기능 보존**: before 위클리 4회 모두 기능을 설명한 출처 47을 인용하지 않았다. 완료된 후보 위클리 2회는 Common/NITROS 릴리스와 상세 기사 47·48을 결합해 에이전트 워크플로와 플랫폼 지원을 설명했다.
- **설계 가이드**: 09-25 Kollmorgen 해설은 before 1/4, 후보 3/4 포함됐다. 개선은 있으나 일관되지는 않다.
- **원문 기반 설명**: 09-10에서는 15건 중 12건의 본문 발췌를 수집했고 3건은 HTTP 실패로 피드 근거를 유지했다. 최종 결과는 systemd-journald 필터링·비동기 링 버퍼, Apache Arrow 기반 RRD·PyTorch 연계, 보호 정지 프로토타입의 미인증 상태를 설명했다.
- **날짜**: 완료된 후보 위클리에서는 Anthropic SDK의 수집일을 릴리스 날짜로 쓰는 기존 오류를 관찰하지 않았다. 날짜를 대체로 생략한 결과이지 실제 사건 날짜를 새로 확보했다는 의미는 아니다.

인용 여부·항목 수·재요청 횟수는 [metrics.json](metrics.json)에 기록했다. 이 지표는 사실 정확성을 채점한 점수가 아니다.

## 남은 문제와 다음 개선 우선순위

1. **문맥과 제품 기능 혼동**: 최종 위클리는 llm-keys-ui 소개의 배경 문장(Codex Remote를 쓰는 작성자의 상황)을 해당 플러그인의 기능처럼 요약했다. 원문 구절을 그대로 인용했어도 그 구절이 요약 주장을 뒷받침하는지는 별도 의미 검토가 필요하다. 근거가 잘린 입력에서는 기능을 단정하지 않는 기준을 강화해야 한다.
2. **유용한 항목 누락**: 최종 위클리에서 Kollmorgen 가이드와 LiteLLM 서명 검증 안내가 제외됐다. 최대 개수를 없애는 것만으로 선정의 완전성이 보장되지 않는다. 제외 이유가 독자 가치 기준에 맞는지 별도 점검이 필요하다.
3. **읽기 부담·순서**: 최종 위클리는 before 15개에서 after 30개 항목으로 늘었다. 항목을 다시 일괄 삭제하기보다 핵심 요약과 추가 읽을거리를 구분하고 중요도순으로 편집하는 것이 적절하다.
4. **세부 한정 표현**: 최종 위클리 IFR 제목의 '돌파'는 입력의 500만 대라는 표현보다 강하다. 검토 모델의 완료 선언과 실제 수정 여부를 동일시하면 안 된다.
5. **원문 수집 한계**: 로그인·접근 제한·동적 렌더링·발췌 상한으로 전체 원문을 확보하지 못한다. 위클리 과거 입력에는 발췌가 없으며 당시 저장 근거만 사용했다.

## 구현·검증

- 원문 발췌 수집, 모든 입력의 선정/제외 이유, 원문에 실제 존재하는 구절 검사, 날짜·인용 검사, 검증 실패 1회 재요청, 별도 검토, 감사 기록을 추가했다.
- 생성 응답의 구조 지정은 [Google GenAI SDK의 JSON response schema](https://github.com/googleapis/python-genai#json-response-schema)를 사용한다. 형식 제약은 의미 정확성 검증을 대체하지 않는다.
- Python 테스트 67개 통과. Astro 빌드 142페이지 성공.
- 평가 실행은 발행·배포를 건너뛰었다. 기존 리포트를 덮어쓰지 않았다.
